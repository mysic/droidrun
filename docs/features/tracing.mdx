Droidrun provides multiple monitoring capabilities:

1. **LLM Tracing** - Real-time execution tracing via Arize Phoenix or Langfuse
2. **Trajectory Recording** - Local screenshots and UI state for debugging

## Quick Reference

```sh
# Enable Phoenix tracing
droidrun run "task" --tracing

# Enable trajectory recording
droidrun run "task" --save-trajectory step
```

---

## LLM Tracing

Droidrun supports two tracing providers for real-time monitoring of LLM calls, agent execution, and tool invocations:

- **Arize Phoenix** (default) - Open-source observability platform
- **Langfuse** - LLM engineering platform with cloud and self-hosted options

Use tracing to debug agent behavior, monitor token usage, and analyze execution flow.

---

### Arize Phoenix Tracing

#### Setup

**1. Install Phoenix:**

```sh
uv pip install arize-phoenix
```

**2. Start Phoenix server:**

```sh
phoenix serve
```

The server starts at `http://localhost:6006` and provides a web UI for viewing traces.

**3. Enable tracing in Droidrun:**

**Via CLI:**

```sh
droidrun run "Open settings" --tracing
```

**Via config.yaml:**

```yaml
tracing:
  enabled: true
```

**Via code:**

```python
from droidrun import DroidAgent, DroidConfig

config = DroidConfig()
config.tracing.enabled = True

agent = DroidAgent(goal="Open settings", config=config)
await agent.run()
```

**4. View traces:**

Navigate to `http://localhost:6006` to see:
- LLM calls with prompts, responses, and token counts
- Agent workflow execution (Manager, Executor, FastAgent)
- Tool invocations and their results
- Execution timings and errors

For more on using Phoenix, see the [Arize Phoenix documentation](https://docs.arize.com/phoenix).

#### Phoenix Configuration

Set environment variables to customize Phoenix:

```sh
# Custom Phoenix server URL (default: http://0.0.0.0:6006)
export phoenix_url=http://localhost:6006

# Project name for organizing traces
export phoenix_project_name=my_droidrun_project
```

<Note>
Environment variable names are lowercase: `phoenix_url` and `phoenix_project_name`.
</Note>

### Langfuse Tracing

Langfuse provides LLM observability with features like session tracking, user analytics, and cost monitoring.

#### Setup

**1. Get Langfuse credentials:**
- **Cloud**: Sign up at [cloud.langfuse.com](https://cloud.langfuse.com)
- **Self-hosted**: Deploy using [Langfuse docs](https://langfuse.com/docs/deployment/self-host)

**2. Configure Droidrun:**
Droidrun 提供多种监控能力：

1. **LLM 跟踪** — 通过 Arize Phoenix 或 Langfuse 进行实时执行追踪
2. **轨迹记录** — 本地保存截图和 UI 状态以便调试

## 快速参考

```sh
# Enable Phoenix tracing
droidrun run "task" --tracing

# Enable trajectory recording
droidrun run "task" --save-trajectory step
```

## LLM 跟踪

Droidrun 支持两个追踪提供者，用于实时监控 LLM 调用、代理执行和工具调用：

- **Arize Phoenix**（默认） — 开源可观测性平台
- **Langfuse** — 提供云端与自托管选项的 LLM 工程平台

使用追踪可以调试代理行为、监控 token 使用并分析执行流程。

---

### Arize Phoenix 跟踪

#### 设置

**1. 安装 Phoenix：**

```sh
uv pip install arize-phoenix
```

**2. 启动 Phoenix 服务：**

```sh
phoenix serve
```

服务器在 `http://localhost:6006` 启动，提供用于查看追踪的 Web 界面。

**3. 在 Droidrun 中启用追踪：**

**通过 CLI：**

```sh
droidrun run "Open settings" --tracing
```

**通过 config.yaml：**

```yaml
tracing:
  enabled: true
```

**通过代码：**

```python
from droidrun import DroidAgent, DroidConfig

config = DroidConfig()
config.tracing.enabled = True

agent = DroidAgent(goal="Open settings", config=config)
await agent.run()
```

**4. 查看追踪：**

访问 `http://localhost:6006` 查看：
- 带有提示、响应和 token 计数的 LLM 调用
- 代理工作流执行（Manager、Executor、FastAgent）
- 工具调用及其结果
- 执行时长和错误

更多使用说明请参见 [Arize Phoenix 文档](https://docs.arize.com/phoenix)。

#### Phoenix 配置

设置环境变量以自定义 Phoenix：

```sh
# Custom Phoenix server URL (default: http://0.0.0.0:6006)
export phoenix_url=http://localhost:6006

# Project name for organizing traces
export phoenix_project_name=my_droidrun_project
```

<Note>
环境变量名称为小写：`phoenix_url` 和 `phoenix_project_name`。
</Note>

---

### Langfuse 跟踪

Langfuse 提供 LLM 可观测性功能，例如会话跟踪、用户分析和成本监控。

#### 设置

**1. 获取 Langfuse 凭证：**
- **云端**：在 [cloud.langfuse.com](https://cloud.langfuse.com) 注册
- **自托管**：参照 [Langfuse 文档](https://langfuse.com/docs/deployment/self-host) 进行部署

**2. 配置 Droidrun：**

**通过环境变量：**
```sh
export LANGFUSE_SECRET_KEY=sk-lf-...
export LANGFUSE_PUBLIC_KEY=pk-lf-...
export LANGFUSE_HOST=https://cloud.langfuse.com
```

**通过 config.yaml：**

```yaml
tracing:
  enabled: true
  provider: langfuse
  langfuse_secret_key: sk-lf-...
  langfuse_public_key: pk-lf-...
  langfuse_host: https://cloud.langfuse.com
  langfuse_user_id: user@example.com  # Optional: track by user
  langfuse_session_id: ""              # Optional: custom session ID
```

**通过代码：**

```python
from droidrun import DroidAgent, DroidConfig, TracingConfig

config = DroidConfig(
    tracing=TracingConfig(
        enabled=True,
        provider="langfuse",
        langfuse_secret_key="sk-lf-...",
        langfuse_public_key="pk-lf-...",
        langfuse_host="https://cloud.langfuse.com",
        langfuse_user_id="user@example.com",
    )
)

agent = DroidAgent(goal="Open settings", config=config)
await agent.run()
```

**3. 查看追踪：**

访问你的 Langfuse 仪表盘查看：
- 包含提示、完成结果及 token 使用情况的 LLM 调用
- 代理执行追踪与嵌套工作流
- 基于会话的分析及成本跟踪
- 用户级指标（如果设置了 `langfuse_user_id`）

更多使用说明请参见 [Langfuse 文档](https://langfuse.com/docs)。

## 轨迹记录

轨迹记录会将截图和 UI 状态保存在本地，用于离线调试和分析。与发送到 PostHog 的遥测（telemetry）和发送到 Phoenix 或 Langfuse 的追踪不同，轨迹文件保存在你的机器上。

### 记录级别

| 级别 | 保存内容 | 何时使用 |
|-------|--------------|-------------|
| `none`（默认） | 无 | 生产环境使用，节省磁盘空间 |
| `step` | 每个代理步骤保存截图与状态 | 一般调试，推荐用于大多数场景 |
| `action` | 每个原子操作保存截图与状态 | 详细调试，捕捉每次点击/滑动/输入 |

**注意：** `action` 级别会生成比 `step` 级别多得多的文件。

### 启用记录

**通过 CLI：**

```sh
droidrun run "Open settings" --save-trajectory step
```

**通过 config.yaml：**

```yaml
logging:
  save_trajectory: step  # none | step | action
```

**通过代码：**

```python
from droidrun import DroidAgent, DroidConfig

config = DroidConfig()
config.logging.save_trajectory = "action"

agent = DroidAgent(goal="Open settings", config=config)
await agent.run()
```

### 输出位置

轨迹保存在当前工作目录下的 `trajectories/`：

```
trajectories/
└── 2025-10-17_14-30-45_open_settings/
    ├── step_000_screenshot.png
    ├── step_000_state.json
    ├── step_001_screenshot.png
    └── step_001_state.json
```

每个轨迹文件夹包含：
- **Screenshots** - 每步的设备屏幕 PNG 图像
- **State files** - 包含以下内容的 JSON 文件：
  - UI 可访问性树（元素层级、ID、文本、边界）
  - 执行的操作（例如 `click(5)`, `type("hello", 3)`）
  - 代理推理和步骤编号
  - 设备状态（当前应用包名、activity）

使用这些文件可以：
- 调试代理为何做出特定决策
- 回放失败执行
- 分析 UI 元素检测问题
- 为改进代理构建训练数据集
