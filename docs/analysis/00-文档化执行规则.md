# 00 文档化执行规则（先执行）

## 1. 目标
本目录用于沉淀 droidrun 源码分析过程，要求所有后续分析结果都形成教程式文档，便于复习、追踪与复查。

## 2. 编号规则
1. 文档统一按两位编号命名：`01-xxx.md`、`02-xxx.md`。
2. 每一轮分析新增一个编号文档，不覆盖历史文档。
3. 若是同一主题追加，创建下一号并在开头写明“承接上一号”。

## 3. 教程式写作规范
1. 先讲“这个模块是做什么的”，再讲“怎么做”，最后讲“为什么这么做”。
2. 每章都包含：
- 学习目标
- 前置知识
- 源码证据（文件路径 + 符号名）
- 步骤化讲解
- 常见坑与排错
- 小结
3. 默认面向“会其他语言、Python 初学者”，优先做跨语言类比。

## 4. 每轮分析的固定输出结构
1. 范围与边界（本轮分析了什么，没分析什么）
2. 架构或流程图谱（可用文字图）
3. 文件级讲解（按目录或职责分组）
4. Python 语法/关键字/内置函数联动说明
5. 不确定项与证据缺口
6. 已覆盖清单与下一轮计划

## 4.1 源码注释同步规则
1. 对已重点讲解的核心代码，优先把讲解性注释放在“代码起始位置前一行”。
2. 如果前一行已有代码，先插入空行，再放注释，避免挤在逻辑代码中间。
3. 注释必须解释“这一段做什么”或“为什么这样设计”，不要重复代码表面含义。
4. 仅给关键类、关键工作流步骤、复杂解析逻辑加注释，避免把源码变成大段噪音。

## 5. 质量门禁（发布前自检）
1. 关键结论必须有证据来源。
2. 不确定项必须显式标记“[不确定]”。
3. 必须给出已覆盖文件清单。
4. 必须给出下一轮建议文件清单。

## 6. 目录协作约定
1. 总索引维护在 `docs/analysis/INDEX.md`。
2. 模板统一在 `docs/analysis/templates/教程式分析模板.md`。
3. 新文档创建后，必须更新索引。
